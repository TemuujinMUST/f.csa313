## Даалгавар 2: Тест дизайн

### Тестлэгдэх функц

`POST /registrations` — оюутныг хичээлд бүртгэх. Оролт: `studentID`, `courseID`.

Серверийн шалгалтын дараалал (`server.js`-ээс): талбар дутуу эсэх → оюутан байгаа эсэх → оюутан идэвхтэй эсэх → хичээл байгаа эсэх → урьдач нөхцөл хангагдсан эсэх.

Семантик: `201` = амжилттай бүртгэл, `200 + ERROR_*` = оролтод суурилсан алдаа, `400` = хүсэлтийн формат буруу.

### Сонголт ба төлөөлөх утгын хүснэгт

| Сонголт | Анги (equivalence class) | Төлөөлөх утга |
|---|---|---|
| studentID-гийн хүчинтэй байдал | Идэвхтэй | `S-ACTIVE`, `{"status":"active"}` |
| | Идэвхгүй | `S-INACTIVE`, `{"status":"inactive"}` |
| | Байхгүй | `S-GHOST` (PUT хийгээгүй) |
| Оюутны үзсэн хичээлүүд | Урьдач хангана | `coursesTaken: ["CS201"]` |
| | Урьдач хангахгүй | `coursesTaken: []` |
| courseID-гийн хүчинтэй байдал | Байгаа | `CS313` (PUT хийсэн) |
| | Байхгүй | `CS999` (PUT хийгээгүй) |
| Хичээлийн урьдач нөхцөл | Бүгд үзсэн | урьдач `["CS201"]`, оюутан `["CS201"]` үзсэн |
| | Огт үзээгүй | урьдач `["CS201"]`, оюутан `[]` |
| | Зарим нь үзсэн | урьдач `["CS201","CS202"]`, оюутан `["CS201"]` |
| | Урьдачгүй (хязгаар) | `prerequisites: []` |
| Хүсэлтийн формат (хязгаар) | Талбар дутуу | `{"studentID":"S-ACTIVE"}` (courseID байхгүй) |
| | Буруу JSON | raw бие `{bad json request}` |

### Боломжгүй / утга алдагдах хослол

- Оюутан **байхгүй** бол "оюутны үзсэн хичээлүүд" гэсэн сонголт утгаа алддаг, учир нь хичээл хадгалах оюутны бичлэг байхгүй.
- Хичээл **байхгүй** бол "хичээлийн урьдач нөхцөл" гэсэн сонголт утгаа алддаг, учир нь урьдач нөхцөл хадгалах хичээлийн бичлэг байхгүй.
- Иймээс сонголтуудын бүх хослол бодит тест болохгүй; ийм хослолууд нэг тест болон нийлдэг.
